# Standalone CLI engine discovery

Run `python check.py --jar <tla2tools.jar> --evidence <output-directory>` from this directory. `--java` selects a Java executable. The driver runs SANY and TLC, writes each checked configuration and log, and records distinct state counts and verdicts in `results.json`.

The model schedules two CLI processes using the same immutable archive digest and data directory. Fifteen initial host/archive/cache combinations cover clean installation, legacy upgrade, native host and cache reuse, missing archive, damaged cache and archive validation failures. Either process may run a command, one may run doctor, or both may run doctor. Host marker classes distinguish a version-only legacy marker, matching and stale archive digests, and an unstamped engine with a matching digest.

`ready` represents the predicate the implementation actually uses for reuse. At discovery time it checks the engine's MZ prefix, footer component and SHA-256 of the image bytes. At first publication it additionally requires successful archive entry validation, complete XZ decoding and rename. The model assumes a stable archive, no process crash, no external filesystem writer, eventual return from I/O and successful cleanup of private files. I/O failure after stage creation is modeled explicitly. An early filesystem failure before creating a stage has no private extraction state. The model abstracts PE bytes, hashes, filesystem errors, OS locking semantics, process execution and the contents of companion assets.

The positive configuration activates all safety properties and eventual settlement under weak fairness for each process. Witness configurations use the correct mechanism and deliberately violate an invariant that denies the target state. Negative controls change the mechanism while retaining its expected property. The runtime tests live in `rust-runtime/crates/cli/tests/contract.rs`.
