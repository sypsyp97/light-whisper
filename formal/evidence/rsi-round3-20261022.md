## Production contracts

The settings hook previously allowed Alibaba key edits after the engine read
completed but before its endpoint read identified the saved region. A key edit
could capture the default international slot even when the persisted region was
domestic. A failed endpoint read after a successful engine change also left the
old region usable; a key-read failure could discard a successful endpoint read.

- Credential edits and clears require a confirmed engine. Alibaba additionally
  requires its current endpoint; GLM's shared credential slot does not.
- Engine, endpoint and key results publish independently. A key failure preserves
  confirmed identity. Failed reads offer inline recovery, without repeating an
  already successful engine mutation.
- Retry reads only failed fields. Confirmed values, valid drafts and pending
  sibling reads retain their ownership. A failed aggregate releases transition
  busy state while the remaining callbacks can still complete.
- Configuration changes retire older read responses. A retry alone does not
  change configuration identity. User edits retire earlier key-read responses.
- A pending retry disables its Retry action without disabling safe GLM edits or
  engine selection. Its busy state belongs to that configuration; an obsolete
  completion cannot clear the busy state of a newer retry.

The existing 600 ms debounce, captured keyring slot, valid-draft unmount flush,
flush-before-switch ordering and abort on save failure remain covered. No
backend API, dependency or visual redesign is introduced.

draft. Existing implementation regressions cover those relevant queue/lifecycle
boundaries. Key text publication and the new Retry-button busy behavior are
unit/UI evidence, not claims of this one-retry model. These are finite safety and
correspondence checks, not source refinement, a native keyring proof, liveness or
unbounded correctness. No new Lean theorem is claimed.
