## Scope and implementation

`scripts/light_whisper_cli.py` drives the existing local engine's JSONL protocol
through `doctor`, `status`, `stats` and file `transcribe` commands. The package
script is `pnpm --silent cli`. It uses only Python's standard library, bounds
startup/request waits, starts a separate owned process, defaults to two CPU
threads and offline model access, and isolates temporary engine data. Explicit
`--data-dir` retains diagnostic logs. Output and error exit codes are documented
in [development instructions](../../docs/development.md#agent-debugging-cli).

The frozen production module's LF-normalized SHA256 is
`7aa551f29b153fb0634bffdff0c79a4773b8a652bdedabfb5e661ddff2ccb885`.
The complete cohort is that module, including its script entrypoint, parser,
command planning, process/pipe/thread ownership and exceptional cleanup.
The source/model/test correspondence table is maintained in
[CLI protocol verification](../cli/README.md).

The desktop app's windows, microphone, hotkeys, cloud providers and live GUI
state are outside this driver's surface. An explicitly selected packaged engine
tests that engine, rather than newly built source DLLs.

## Test-first development and review

The original application has no CLI API: its initial RED was explicitly
declaration-scaffold based, not an old-application regression. Dedicated Test
Writers authored the tests, finite models and measurement configuration before
production implementation. Main integrated the accepted slices.

Independent lifecycle review subsequently found two real regressions: reader
setup could fail after acquiring a process without releasing it, and an
interruption during cleanup could bypass forced termination or try to join an
unstarted worker. A new test-first slice demonstrated eight assertion failures,
including watchdog-contained blocking cleanup, before the production repair.
The final source and model correspondence received independent ACCEPT.

The final strengthened cohort has 39 CLI tests, GREEN on supported CPython
3.11.11 and measurement CPython 3.13.2. Its LF-normalized test SHA256 is
`c889f86279431237d6ddda342dc259b18b8e6132bc78b754fa98a93273ead61f`.
Forty-two exact source-mutant controls demonstrated semantic failures before
acceptance. These cover integer identities beyond CPython's small-integer cache,
independently validated arguments, nested data paths, broken stdin and shared
deadline schedules, including both insufficient and excessive cleanup waits.
The quantitative cases use explicit standard-library dispatch controls around
real children/threads; they are not claims about arbitrary OS scheduling.

Two further real-script regressions reproduced missing JSON and wrong exit codes
when redirected Windows stdout used CP1252 and a path/error contained Chinese
characters. After RED on both Python versions, final JSON serialization was
changed to ASCII escaping. Decoded Unicode values are preserved. Independent
drift review confirmed this one-line fix leaves the modeled lifecycle unchanged.

Coverage instrumentation then exposed a real handoff race: a queued successful
write outcome could precede writer termination, allowing a response to return
with a live sender and causing cleanup to skip graceful exit. Two deterministic
public-client regressions produced three assertion failures before the repair.
Successful sends now join their writer within the original request deadline and
raise `TimeoutError` if the writer remains alive. A three-line drift review and
38-test GREEN runs on both Python versions accepted the repair.

Mutation review then exposed a masked receiver test: an earlier sender timeout
could prevent the receiver from being exercised. An additional public-client
schedule waits for actual sender termination before advancing the clock and
checks partial/expired receive budgets. The correct source remained unchanged;
negative-clamp and modulo mutants now produce explicit semantic failures.

## Finite verification

The positive TLC run generated 5,462 states, with 2,420 distinct states and search
depth 18. The model has one serial client, one owned process, at most two request
identities and one representative nonmatching identity. It separates acquisition,
reader setup, startup, request publication, timeout/EOF, graceful exit,
termination, worker joins and reap, including bounded setup/cleanup faults.

The original 14 configurations reached their expected outcomes: one positive exhaustive
check, six safety negative controls, two progress negative controls and five
reachability witnesses. Negative controls fail their named property; witnesses
demonstrate reachable states. They are not additional positive proofs.

The supplemental sender model checks the acknowledged-but-live worker boundary
after startup, with two serial requests, two writer identities and an original
budget of two abstract ticks. Dispatch representatives cover full, partial,
just-exhausted and already-expired budgets. Its positive run generated 3,076
states, with 1,284 distinct states and depth 19. Eight supplemental configurations
reached their expected outcomes: one positive, three safety negatives, one
progress negative and three witnesses. The combined matrix has 22 configurations.
These separate finite models are not an automatic composition or source
refinement proof. The supplemental reap state records child reap before final
worker joins, not a guarantee that arbitrary stalled threads have terminated.

TLC used one worker, a 512 MiB JVM heap and the existing pinned JAR with SHA256
`936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88`.
Weak fairness assumes responsive OS scheduling and successful kill/wait. The
model does not prove wall-clock deadlines, arbitrary repeated asynchronous
faults, arbitrary descendants or source refinement.
